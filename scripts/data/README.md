# data acquisition scripts

- `run_calendar_maintenance_refresh.py` plans or runs the shared bounded calendar maintenance refresh. It combines daily Trading Economics recent/future macro release-preview discovery, shared release-fetch queue updates, Nasdaq earnings schedule source-artifact discovery, and NYSE official exchange holiday/early-close discovery. The exchange-calendar route overlays `trading_data.calendar_market_session`; none of these routes populates M06 event-governance SQL rows.
- `run_trading_economics_release_fetcher.py` runs the single shared TE release-fetch worker. It reads the shared queue, processes due release windows, polls every 5 seconds for up to 60 seconds, and writes provisional web-search fallback evidence only when no formal TE actual appears.
- `fetch_tradingview_equity_screener.py` writes a bounded no-login TradingView US common-stock screener snapshot for realtime traded-dollar-value, market cap, and sector evidence. The default request takes the top 300 names by each rank.
- `build_equity_total_symbol_pool.py` builds the reviewed realtime equity total-symbol pool ledger from TradingView screener CSVs and optional optionable-symbol lists. The CSV keeps observed inactive rows; the adjacent symbols text file contains only active rows.
- `refresh_equity_total_symbol_pool_from_tradingview.py` runs the TradingView snapshot and rebuilds the shared realtime pool. The accepted scheduler cadence is every 30 minutes. Until a strict optionable source is supplied, its default mode keeps active rows marked `uncertain_verify_before_use` in the calendar symbol text file so the calendar lane can proceed without pretending optionability is verified. Historical replay must use its frozen candidate-universe table instead of reading this mutable realtime pool directly.
- `build_historical_candidate_universe.py` freezes a static historical replay candidate table from provider-derived active realtime equity pool rows plus the reviewed BTC/ETH/SOL crypto spot candidate pool. It preserves TradingView's raw sector, maps equities to the accepted M02 SPDR sector anchors, and maps crypto spot rows to the accepted `BKCH` context anchor while marking listed options as structurally not applicable.
- `run_trading_economics_recent_calendar_refresh.py` plans or runs the bounded Trading Economics recent/future calendar refresh. It writes canonical storage source rows only when new or changed release-preview/release facts are observed, cleans up no-op refreshes, can poll release-time windows until an `actual` value appears, and must not persist TE website URLs or populate M06 event-governance SQL rows. Its web-search fallback output is provisional realtime decision evidence, not TE-origin source data.
- `run_trading_economics_authenticated_historical_backfill.py` runs a bounded authenticated month-by-month Trading Economics historical calendar backfill for canonical storage source artifacts. It uses the visible calendar page with authenticated cookies, writes `Actual`, `Previous`, `Consensus`, and `Forecast` fields when present, and must not call TE API/download/export endpoints, persist website URLs, populate M06 SQL rows, train models, activate models, or touch broker/account state.
- `build_calendar_observations.py` builds unified `calendar_observation` source-shell artifacts from accepted calendar inputs such as market-session rules, option-expiry rules, official exchange calendar rows, headline index methodology/announcement rows, Trading Economics calendar rows, and SQL-retained calendar-discovery rows. These artifacts are scheduling/source observations only; M06 residual event governance must explicitly promote relevant rows before they become event-pool entries.
- `install_temporal_explorer_tables.py` installs the provider-neutral Temporal Explorer SQL substrate, upserts deterministic day/session spine rows, and can overlay accepted official exchange holiday/early-close rows. It does not call providers or populate chart bars.
