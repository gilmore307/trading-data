# data acquisition scripts

- `run_calendar_maintenance_refresh.py` plans or runs the shared bounded calendar maintenance refresh. It combines Trading Economics recent/future macro calendar maintenance, Nasdaq earnings schedule source-artifact discovery, and NYSE official exchange holiday/early-close discovery. The exchange-calendar route overlays `trading_data.calendar_market_session`; none of these routes populates Layer 10 SQL event-pool rows.
- `fetch_tradingview_equity_screener.py` writes a bounded no-login TradingView US common-stock screener snapshot for realtime traded-dollar-value, market cap, and sector evidence. The default request takes the top 300 names by each rank.
- `build_equity_total_symbol_pool.py` builds the reviewed realtime equity total-symbol pool ledger from TradingView screener CSVs plus an optional optionable-symbol list. The CSV keeps observed inactive rows; the adjacent symbols text file contains only active rows.
- `refresh_equity_total_symbol_pool_from_tradingview.py` runs the TradingView snapshot and rebuilds the shared realtime pool. The accepted scheduler cadence is every 30 minutes. Until a strict optionable source is supplied, its default mode keeps active rows marked `uncertain_verify_before_use` in the calendar symbol text file so the calendar lane can proceed without pretending optionability is verified. Historical replay must use its frozen candidate-universe table instead of reading this mutable realtime pool directly.
- `build_historical_candidate_universe.py` freezes a static historical replay candidate table from the current active realtime pool plus BTC, ETH, and SOL. It preserves TradingView's raw sector and maps equities to the accepted Layer 2 SPDR sector anchors; crypto targets map to `BKCH`.
- `run_trading_economics_recent_calendar_refresh.py` plans or runs the bounded Trading Economics recent/future calendar refresh. It appends canonical storage source rows only and must not persist website URLs or populate Layer 10 SQL rows.
- `build_calendar_observations.py` builds unified `calendar_observation` source-shell artifacts from accepted calendar inputs such as market-session rules, option-expiry rules, official exchange calendar rows, headline index methodology/announcement rows, Trading Economics calendar rows, and SQL-retained calendar-discovery rows. These artifacts are scheduling/source observations only; Layer 10 must explicitly promote relevant rows before they become event-pool entries.
- `install_temporal_explorer_tables.py` installs the provider-neutral Temporal Explorer SQL substrate, upserts deterministic day/session spine rows, and can overlay accepted official exchange holiday/early-close rows. It does not call providers or populate chart bars.
